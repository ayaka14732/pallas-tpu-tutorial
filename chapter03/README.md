# 第三章：静态分析与计时

前两章研究了每种操作由哪些指令完成、数据经过哪些通路，引用的时延都来自实测。本章讲这些数字是怎样测出来的，以及怎样从清单预先估算执行时间。

时间可以在两处测：主机上的调用时间，和设备上的周期计数器。本教程首选后者：读数就是周期，可以放在程序的任何位置。本章从最粗的主机计时开始，说明它包含什么、为什么不够，再深入到设备上的单个周期，最后把结论整理成一个可以从清单推算周期数的发射模型。JAX 自带的 profiler XProf 只用一节介绍：它的事件怎样产生、怎样解析，以及哪些信息只有它能给出。

读完本章，应当能够：

- 说清一个“时间”从哪里开始、到哪里结束，包含哪些与 kernel 无关的开销；
- 公平地比较两个实现，并从编译结果判断两边是否做了同一件事；
- 用设备上的 LCC 测量一个 kernel 或其中的一段代码，知道读数的边界在哪里；
- 读懂 XProf 的事件来自哪条指令，需要时自己写出这条指令；
- 理解 TensorCore 的两级发射，判断何时需要 `sfence`；
- 从清单推算一段代码的周期数，并用 LCC 验证；
- 用 GTC 比较不同 TensorCore、不同芯片上的事件。

## 本章的工具

计时用 [`tpuasm_tools.py`](../tpuasm_tools.py) 中的两个工具，都在第 4 节介绍。`LccProbe` 用 Pallas 编译一个载体 kernel，再用 tpuasm 在其中插入手写的 bundle，读出 LCC 或 GTC；插入的片段不经过编译器，设备执行的就是写下的指令。`KernelClock` 给任意已编译的程序计时：在指定的位置插入 LCC 读数，读数留在 SMEM 中，程序运行之后取回。第 3 节用 [`xprof_tools.py`](../xprof_tools.py) 采集并解析 XProf 的 XPlane 文件。

| XLU 跨 lane 归约：提交 → 取回 / 提交指令的发射间隔 | 79 / 8 个周期 | 第 6 节 |
