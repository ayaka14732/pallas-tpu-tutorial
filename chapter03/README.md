# 第三章：静态分析与计时

前两章研究了每种操作由哪些指令完成、数据经过哪些通路，引用的时延都来自实测。本章讲这些数字是怎样测出来的，以及怎样从清单预先估算执行时间。

时间可以在三处测：主机的时钟，以及设备上的两个计数器。

- **主机的时钟**测到的是调用方等待的时间，包含提交、启动和完成通知，与 kernel 本身关系不大。
- **LCC**（local cycle counter）是每个 TensorCore 自己的周期计数器，每个周期加 1。在一个 TensorCore 上数一段代码要多少周期，用它：读数就是周期，可以放在程序的任何位置。本教程中的周期数都是这样测的。
- **GTC**（global time counter）是整个切片共用的时间轴，各芯片通过一棵时钟同步树对齐到同一个时间源。比较不同 TensorCore、不同芯片上的事件，或者把一段时间换成秒，用它。JAX 自带的 profiler XProf 的设备时间就来自 GTC。

两个计数器不能互相替代：LCC 的读数只在同一个 TensorCore 之内可比；GTC 的分辨率是 1.5 个周期，在时间源之外的芯片上还会被不断校正。

本章从最粗的主机计时开始，说明它包含什么、为什么不够；再用 LCC 深入到设备上的单个周期，把结论整理成一个可以从清单推算周期数的发射模型；然后介绍 GTC 和时钟同步树；最后介绍建立在 GTC 上的 XProf：它的事件怎样产生、怎样解析，以及哪些信息只有它能给出。

读完本章，应当能够：

- 说清一个“时间”从哪里开始、到哪里结束，包含哪些与 kernel 无关的开销；
- 公平地比较两个实现，并从编译结果判断两边是否做了同一件事；
- 用设备上的 LCC 测量一个 kernel 或其中的一段代码，知道读数的边界在哪里；
- 理解 TensorCore 的两级发射，判断何时需要 `sfence`；
- 从清单推算一段代码的周期数，并用 LCC 验证；
- 说清 GTC 的读数由哪两部分组成，时间源与跟随者读到的 GTC 有什么不同，并用 GTC 比较不同 TensorCore、不同芯片上的事件；
- 读懂 XProf 的事件来自哪条指令、时间来自哪个计数器，需要时自己写出这条指令。

## 本章的工具

计时用 [`tpuasm_tools.py`](../tpuasm_tools.py) 中的两个工具，都在第 3 节介绍。`LccProbe` 用 Pallas 编译一个载体 kernel，再用 tpuasm 在其中插入手写的 bundle，读出 LCC 或 GTC；插入的片段不经过编译器，设备执行的就是写下的指令。`KernelClock` 给任意已编译的程序计时：在指定的位置插入 LCC 读数，读数留在 SMEM 中，程序运行之后取回。第 6 节用同一个 `LccProbe` 读 GTC，并从主机只读地读回同步树的角色寄存器。第 7 节用 [`xprof_tools.py`](../xprof_tools.py) 采集并解析 XProf 的 XPlane 文件。
